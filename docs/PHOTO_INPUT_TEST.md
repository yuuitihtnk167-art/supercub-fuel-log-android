# 写真取得の実機確認（Issue #4）

写真管理の回帰確認手順。ChatGPT共有の追加確認は[共有確認手順](CHATGPT_SHARING_TEST.md)を参照する。
写真のクラウド保存は行わない。既存のJSON貼り付け・手入力・保存処理を維持する。
保存テストは利用者の確認後に行い、既存Firestore記録の編集・削除はしない。

## Pixel 7 Proで確認する操作（未実施）

1. 新規記録で日付・走行距離・給油量を入力。入力欄タップではキーボード、右端のカメラアイコンでは「画像を選択」「カメラで撮影」が開くこと。
2. メーター画像を選択し、縮小画像が表示されること。選び直し・撮り直しの成功時だけ置き換わること。
3. レシートを1枚登録した後、写真の下にある「レシートを追加（2枚目）」を押し、「画像を選択」「カメラで撮影」をそれぞれ試す。1枚目が残って2枚目が追加され、2枚揃うと追加ボタンが消えること。各写真の「差し替え・撮り直し」「削除」が他方の写真を変更しないこと。2枚まとめて選ぶ操作と、2枚目の取得キャンセルで1枚目・メーター・入力が保持されることも確認する。
4. 画像取得メニュー、画像選択、カメラをそれぞれキャンセルし、既存画像と全入力が変わらないこと。
5. 同じファイルを再度追加すると拒否され、他の画像も変わらないこと。別撮影の同じレシートは自動判別できないため目視確認する。
6. 2枚ある状態で給油量欄のアイコンから追加を試し、上限の案内が出ること。
7. 回転、ホーム画面との往復、カメラ・画像選択から復帰、バックグラウンドでのプロセス終了後の復帰で画像と入力の保持を確認する。
8. コピー中の中断では既存画像を保持し、再選択できること。取得待ちが残った場合は「画像の取得を中止」から復帰する。
9. ログアウト・別アカウントへの変更後に以前の画像・入力が出ないこと。承認取り消しの検証はテストアカウントで行い、Firestore記録は変更しない。
10. 写真追加後もJSON貼り付けと手修正が使えること。不正値のJSONを貼り付ける前後の両欄を比較し、部分更新が一切ないこと（既存の未確認項目）。

## 保持と制限

- 選択画像はアプリ専用キャッシュへコピーする。元画像は変更・削除しない。
- 撮影・選択画像の内容が読み取れることを確認してから全体を反映する。読み取り不能・32MB超・枚数超過・同一内容の重複では既存画像を維持する。
- 一時画像・取得要求・入力の参照はSavedStateHandleで保持する。OSのキャッシュ削除、強制停止、タスク破棄後の復元は保証しない。消えた画像は再取得する。
- 保存成功、新しい編集対象への切替、編集キャンセル、ログアウト、アカウント変更、承認取り消しで一時画像を破棄する。通信による承認再確認中は同じユーザーの写真を保持し、承認が戻るまで表示しない。
- 写真だけでは入力値を変更しない。ChatGPT共有後も、JSON検証・変更確認を経て反映する。
