# ChatGPT画像共有（Issue #4）

## 調査結果と実装

- Android公式のSharesheetではACTION_SEND（1枚）／ACTION_SEND_MULTIPLE（2〜3枚）、EXTRA_STREAM、EXTRA_TEXTを使える。画像と指示文を同じIntentへ格納する。
- 画像はFileProviderのcontent URI、全画像を含むClipData、一時的な読み取り権限で渡す。共有時に書き込み権限は付けない。元の画像・入力は共有キャンセルでも残す。
- 共有先は標準画面で利用者がChatGPTを選択する。ChatGPTの非公開ActivityやURL、OpenAI APIは使わない。
- Pixel 7 Proのインストール済みChatGPT 1.2026.307について、image/*のSEND／SEND_MULTIPLE受信フィルターをADBで確認した。これは指示文の取り込み・画像3枚の表示・解析開始を保証するものではない。
- 確認したOpenAI公式資料ではAndroid共有Intentの画像・テキスト同時受信を保証する契約は確認できなかった。実際の受信動作は未検証。指示文が取り込まれない場合は「解析指示をコピー」から手動で貼り付ける。
- 共有画面を開けたら主ボタンを「貼り付け」にする。共有先選択のキャンセルや解析成功は判定せず、「もう一度解析する」で復帰できる。
- 復帰だけではクリップボードを読まない。「貼り付け」を押す→JSON全体検証→変更前後の確認→「反映する」の順。空・不正JSONは入力と貼り付け待ちを保持する。変更がない有効JSONは通知して解析状態へ戻る。
- 写真変更、新規記録、保存成功、ログアウト・アカウント変更・承認取り消しでは解析状態へ戻す。同一ユーザーの承認再確認中は入力・写真・待機状態を保持する。
- 手入力・写真なしのJSON利用は「JSONを直接貼り付け」から可能。保存ボタンを押すまでFirestoreには書き込まない。

## Pixel 7 Proで確認する手順（共有・受信は未実施）

1. 更新版アプリをRun。画像0枚で「ChatGPTで解析」を押し、案内が出て共有画面へ進まないこと。
2. メーターだけ、レシートだけ、レシート2枚、メーター＋レシート2枚の各組み合わせで共有する。
3. 共有画面でChatGPTを選択。画像が1／2／3枚取り込まれたか、指示文も入ったかをそれぞれ記録する。自動で解析が始まると仮定しない。
4. 指示文が欠ける場合はアプリへ戻り「解析指示をコピー」。再共有し、ChatGPTの入力欄へ指示文を貼り付ける。
5. ChatGPT側で画像・指示文を確認し、送信する。JSONの回答をコピーしてアプリへ戻る。
6. 主ボタンが「貼り付け」になっていること。押すと確認画面が出て、確認前は両欄とも変更されないこと。「反映する」で数値だけが入ること。
7. 68982.6 km・0.13 L、2枚合計2.13 Lの小数を確認。片方のレシートが読めない場合はfuel_lがnullで、既存入力を消さないこと。
8. コピーせず帰還／クリップボード空／不正JSON／有効値と負数の混在を試す。入力が部分更新されず、貼り付け待ちを維持し、再解析できること。
9. 共有キャンセル、ChatGPTが共有先にない場合も画像・入力を保持すること。「もう一度解析する」で再共有できること。
10. 待機中に写真の追加・削除・差し替えを行い「ChatGPTで解析」へ戻ること。回転・ホーム往復・同一アカウントでの承認再確認では待機状態が残ること。
11. 保存テストは利用者の確認後に別途行う。既存のFirestore記録は編集・削除しない。

## 制限

ChatGPT側での送信、回答のコピー、アプリへの復帰は手動。回答の自動回収・自動貼り付け・自動保存はしない。
写真は一時キャッシュなのでOSによる削除やタスク破棄後の保持は保証しない。
古いJSONが残ったクリップボードを2つの数値キーだけで自動識別することはできない。最新の回答をコピーし、反映前に数値を確認する。
